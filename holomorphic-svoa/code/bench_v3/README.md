# Benchmark-v3 worker sources (archive for replay)

Generated by `tools/package_bench_sources.py` (workspace). The files keep their workspace-relative layout under
`claude/`, so the workers find their imports as they did when they ran; they still use the older internal names
(ring, cyc/nega, delayed). `SOURCES.json` maps every source hash recorded in the lanes' `runs.jsonl` to the packaged
file (the version used by the most recent run is at its normal path, older recorded versions in `older_versions/`),
and lists the dependencies whose version at run time was not recorded (copied at their current version).

`runs/<lane>.jsonl` are the lanes' run records (time, seed, argv, Python and numpy versions, source hashes), with the
local workspace path replaced by `<workspace>` and the process-ID fields removed; timestamps and all other fields are
unchanged.

To replay a run, restore its sources by run id: `python3 restore_run.py LANE RUN SCRATCH` (for example
`python3 restore_run.py bench3_k21b 3 /tmp/replay`) copies every source file whose SHA-256 that run recorded to its
original workspace-relative path under `SCRATCH`, checks each hash again, adds the unrecorded dependencies at their
archived version (with a warning), writes `SCRATCH/RESTORED.json`, and prints the recorded argv (with the recorded
seed) to start in `SCRATCH/claude/persistent/mixed_rings`; install numpy and sympy first. The worker draws its pools
and candidates from `numpy.random.default_rng(seed)`, so the replay repeats the run's sequence of candidates; the
pool RNG states are logged per pool in each lane's `epochs.jsonl`, in the audit bundle `../../data/`. Check of
19 Oct 2026: `bench3_k6` run 0 restored this way (its older `bench_worker.py` comes from `older_versions/`) and
replayed for 9 s reproduced the run's first journalled hit exactly: pool, cell tuple, closure, index and rowspace
hash.

Every source version recorded in a run record is in this archive. That is narrower than reproducing the historical execution environment: the run-time versions of the unrecorded dependencies, the Python and numpy builds (the run records give their version numbers) and the platform are not reproduced.

Publication edits: in `claude/k24_transfer/kspan_rings.py` one docstring phrase about internal workflow removed (lines 1-2); the code is unchanged. Its packaged SHA-256 (652d6f1cc0e0…) therefore differs from the one recorded in the run records (8aa41220a358…), which `SOURCES.json` keeps as provenance next to the packaged hash (`packaged_sha256`); `restore_run.py` accepts this documented difference and reports it.
